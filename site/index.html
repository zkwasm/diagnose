WHAT · AN OPEN-SOURCE BRIDGE TO ON-SITE DEVICES

Bring your AI agent to devices in the field.

Troubleshoot a home IoT gateway, a factory controller, or an industrial PC through a computer nearby. Diagnose connects your AI agent to that computer, so it can inspect the device, carry out authorized repairs, and check the result.

Connect a supported data cable, or use a device the computer can reach on its local network.

Start and approve

Start the probe, share its nine-letter invitation privately, and approve the connection. The code lasts 30 minutes and works once.

03 / REMOTE

Describe the fault and the desired result. Optionally load a device-specific Markdown procedure.

Investigate and repair

The agent reads evidence and uses available tools. The user controls permission for operations.

Check the device

Repeat a device health check or confirm that its data is arriving. Review what happened in local history.

EXAMPLE · A HOME IOT GATEWAY

“The gateway is online, but no readings are arriving.”

The owner connects its exposed serial interface to a laptop and starts Diagnose. A remote expert asks the AI to inspect logs and check communication with the sensors. If the available interface supports a repair, the AI can apply it with permission and check for new readings. Otherwise, it reports the evidence and the required on-site action.

WHAT YOU CAN REACH

Work where
the problem lives.

One general-purpose probe, different device procedures. Access depends on the device’s exposed interfaces, credentials, drivers, and tools.

[01]

USB & serial devices

Read exposed serial logs from a gateway or controller. Use installed vendor tools for other USB interfaces; a USB connector alone does not guarantee diagnostic access.

serial.capture · serial.exchange · process.run
[02]

Devices on the local network

Reach an IoT gateway, industrial PC, or device service that the on-site computer can access. Use existing protocols and credentials through a scoped connection.

net.forward · local / remote / socks
[03]

Your device knowledge

Load a Markdown file with the model, protocol, diagnostic steps, and checks. The same probe can support different devices without a custom diagnostic app for each.

diagnose agent codex --skill ./device.md
[04]

The computer that connects them

Inspect drivers, local services, files, and network settings when they are part of the device problem. The computer itself can be diagnosed too.

system.inspect · process.open · file.transfer

POWER THAT STAYS VISIBLE

The user keeps
the controls.

Device access can change real settings. The person on site decides what is allowed.

REVIEW

Review the work.

Review each operation or batch and its result transmission. Live channels ask for continuing raw input/output before they open.

DELEGATE

Choose automatic mode.

The user can explicitly allow execution and transmission for one hour, or until revoked for a remembered pairing. The remote agent cannot enable it.

REVOKE

Take back control.

Use permissions ask to revoke, cancel to stop work, pause to block access, or unpair to revoke the relationship.

◇

End-to-end encryption protects traffic from the relay. The diagnostician and their AI provider can see results. Approved commands have the user's OS permissions; this is not a sandbox. Raw terminal, file, and TCP channels are not redacted.

FROM ONE DEVICE TO THE NEXT

Turn field experience
into reusable procedures.

Keep the evidence behind a diagnosis, review what the agent learned, and bring the resulting skill to another computer. Available in Diagnose 0.6.

[01]

Record the actual device problem

A diagnosis case separates the on-site computer from the gateway or controller. Keep received evidence, changes and verification together.

[02]

Let the agent propose a procedure

Turn useful findings into a skill draft, or propose an improvement to the version used. Include prerequisites, failed approaches and checks for success.

[03]

Review before reusing

Inspect the proposed changes and evidence in your terminal. Remove customer details, accept a new version, and keep the old one available.

diagnose drafts review DRAFT_ID
[04]

Take your knowledge with you

Use skills locally or explicitly sync complete versions through an encrypted personal library. Restore on another computer with your private recovery file. Raw case logs are not synced automatically.

diagnose vault pull

A few useful answers.

Does Diagnose support every device?

No. The on-site computer must be able to communicate with the device through an available interface. Drivers, credentials, protocol knowledge, or vendor tools may be required. Diagnose provides access and execution tools; your agent and device procedure determine how to use them. It cannot repair a broken cable or perform physical work.

Can the agent fix problems, or only collect logs?

It can run commands and scripts, edit configuration, and use device tools within the user's authorization. Ask it to explain the proposed repair, apply only authorized changes, and repeat the original check. A successful command alone does not prove the problem is fixed; arbitrary changes are not automatically rolled back.

Does the user need Codex or an AI account?

No. The user only needs Node.js and the Diagnose probe. The diagnostician runs and authenticates the AI agent on their own computer.

Can I review what happened afterward?

Run diagnose history and diagnose show TASK_ID on the user computer to review encrypted task details, collected results, and approval and transfer events. Records have bounded storage and seven-day inactive retention. Use diagnose cleanup --days 0 to remove inactive records. Arbitrary script side effects are not fully tracked. See the history guide.

What does the relay know?

The relay forwards ciphertext and cannot decrypt diagnostic contents. It can observe IP addresses, routing identifiers, connection times, and traffic volume, and can interrupt service. The protocol has not undergone an independent security audit.

Can I run my own relay?

Yes. The source and deployment templates are available under the MIT license. Pass your relay URL to the probe and agent launcher. See the deployment notes.

Which platforms have been tested?

The probe and agent launchers have been tested on macOS, and the relay on Linux. Automated CI covers macOS/Linux and targeted Windows regressions. Windows interactive terminals, authentication, and physical USB/serial behavior still need real-environment validation.
